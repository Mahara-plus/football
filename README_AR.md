# تحدي كرة القدم — مشروع Android + Backend (نسخة تطويرية)

## ما أُضيف في هذه المرحلة
- تسجيل حساب وتسجيل دخول عبر API (كلمات المرور تُخزّن كـ bcrypt hashes).
- إنشاء غرفة برمز والانضمام إلى غرفة.
- نقطة بداية لـ Socket.IO للأحداث المباشرة ورسائل الغرفة.
- تصنيف عالمي يعتمد على نقاط المستخدمين.
- قاعدة PostgreSQL للجداول: المستخدمون، الأسئلة، الغرف، لاعبو الغرف.
- Redis adapter لـ Socket.IO عند تشغيل أكثر من نسخة من الخادم.
- إعدادات اللعبة المحلية: عدد الجولات، اللاعبين، وأسئلة انتقالات/عامة/تخمين لاعبين.
- رفع نقاط نتيجة اللعبة إلى الخادم.

## تشغيل الخادم محلياً
1. ثبّت Node.js 20+ وDocker.
2. من مجلد backend شغّل: `docker compose up -d`
3. انسخ `.env.example` إلى `.env` وغيّر `JWT_SECRET` إلى قيمة طويلة عشوائية.
4. نفّذ `npm install` ثم `npm start`.
5. اختبر `http://localhost:3000/health`.

## ربط تطبيق Android
- شغّل الخادم على عنوان يمكن للهاتف الوصول إليه.
- افتح التطبيق > إعداد عنوان الخادم، واكتب عنوان API، مثال `http://192.168.1.20:3000`.
- لا تستخدم `10.0.2.2` إلا داخل محاكي Android.
- للتشغيل العام استخدم HTTPS، ولا تترك CORS مفتوحاً (`CORS_ORIGIN=*`) في الإنتاج.

## بناء APK
ارفع المشروع إلى GitHub، ثم افتح Actions وشغّل workflow `Build Android APK`. نزّل Artifact `FootballChallenge-debug-apk` بعد نجاح البناء، وفك ضغطه وثبّت `app-debug.apk`.

## حدود مهمة — لا تعتبرها جاهزة لـ 100 ألف لاعب بعد
هذه بنية بداية قابلة للتوسعة وليست إثباتاً لقدرة 100 ألف اتصال متزامن. يلزم قبل إطلاق عام:
- نشر API خلف Load Balancer مع عدة نسخ stateless.
- Redis مُدار عالي التوافر مع Socket.IO adapter، وتخزين حالة المباريات/الأحداث بشكل متين.
- PostgreSQL مُدار مع connection pooling ونسخ احتياطي وفهارس ومراقبة.
- حدود طلبات، حماية من إساءة الاستخدام، تحقق بريد/استعادة حساب، إدارة جلسات وأمان أسرار.
- اختبارات تحميل واقعية إلى 100k اتصال/مستخدم متزامن وتوسيع الموارد حسب النتائج.
- نظام إدارة محتوى للأسئلة ومراجعتها؛ لا يوجد حالياً بنك ضخم جاهز. الأسئلة المضمنة تجريبية ومحدودة.
- أحداث الغرف موجودة كنقطة بداية، لكن مزامنة جولات اللعبة الفعلية، المؤقت، احتساب الإجابات ومنع الغش ما زالت تحتاج تنفيذ واختبار.
- تسجيل الدخول عبر Google والدردشة الكاملة ولوحة الإدارة ليست مكتملة بعد.

## ملاحظات أمان
ملف Android يسمح مؤقتاً باتصالات HTTP للتطوير. في الإنتاج يجب استخدام HTTPS وإيقاف cleartext traffic. لا ترفع ملف `.env` أو أسرار JWT إلى GitHub.
